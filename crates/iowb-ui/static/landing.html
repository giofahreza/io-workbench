01 / a working session

The work should carry its own context.

A remote session is useful only when it keeps the state that explains it. io-workbench gives every request a visible route from project to proof.

  1. 01

    Start on the actual project

    The host owns the repository, configured provider CLIs, credentials, processes, databases, and PTY.

  2. 02

    Choose the tool that moves it forward

    Use an agent, files, Git, a database, or a live shell without losing the project around the task.

  3. 03

    Leave an answer someone can verify

    Keep the decisions, commands, outputs, rows, diffs, and checks attached before the work moves on.

THE BENCH

02 / work surfaces

Every tool sees the same work.

The screen changes with the moment. The host, the project, and the evidence do not.

01 / agents

Use the right model without leaving the bench.

Launch or resume configured Claude, Codex, and Gemini CLI sessions in the same project context.

  • Provider sessions stay scoped to the project
  • Streaming, reconnect, and recovery remain visible

02 / terminal

A real remote PTY, not an output pane.

Type, resize, paste, follow live output, and control the process where the workload is actually running.

03 / data

Bring the schema into the conversation.

Connect databases, trace relationships, run SQL, and inspect the rows behind a change.

04 / delivery

Make agent work legible before it ships.

Scope the task, approve the plan, add validation, and keep the Git trail attached from backlog to done.

03 / why it holds together

The answer is only one part of the work.

io-workbench keeps the artifacts that make an answer useful: state, commands, outputs, rows, diffs, decisions, and the next check. That is what turns an agent session into work someone can review.

04 / bring up a host

Start where the real tools already live.

Run the host on Linux, macOS, or Windows. Then connect from the screen that is in front of you.

Linux / macOS
curl -fsSL https://github.com/giofahreza/io-workbench/releases/latest/download/install.sh | sh
Windows PowerShell
irm https://github.com/giofahreza/io-workbench/releases/latest/download/install.ps1 | iex
Verify the host
io-workbench doctor --require-running
HOST

Keep it on the machine that owns the repositories, provider logins, processes, and databases.

ACCESS

Keep loopback by default. For remote access, use an intentional HTTPS and WebSocket-capable VPN, proxy, or tunnel.

CLIENTS

Web, desktop, Android, and the PWA are control surfaces. They do not move the work off your host.
