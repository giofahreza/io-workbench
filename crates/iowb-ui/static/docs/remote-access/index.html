TopicsMobile clientsNative desktop clientRemote access and security

The default server binds to 127.0.0.1:8787, which is ideal for first-run setup. Remote use is a network-design decision: place a VPN, authenticated tunnel, or HTTPS/WSS reverse proxy in front of the control plane before a phone or outside browser connects.

Choose a boundary

BoundaryUse it whenWhat to verify
VPNYour devices are already members of a private network.The VPN address reaches the host, the firewall is narrow, and the client receives an HTTPS/WSS path when needed.
HTTPS reverse proxyYou operate a hostname and want normal browser/mobile access.TLS termination, proxy authentication, /ws upgrade support, and a trusted upstream listener.
Authenticated tunnelYou need selective remote access without opening inbound firewall ports.The tunnel requires identity checks and forwards HTTP plus WebSocket traffic to the local service.
Trusted LANTemporary access is limited to a private network you control.The listener/firewall is scoped narrowly and no public route can reach it.

Temporarily listen on a trusted LAN

Only do this when the LAN is intentionally trusted and the host firewall scope is understood. Keep authentication enabled.

Shell
IO_WORKBENCH_HOST=0.0.0.0 IO_WORKBENCH_PORT=8787 cargo run -p iowb-cli --bin io-workbench -- start

Do not publish a development listener

Never disable authentication or bind broadly merely to make a phone connect. Use a VPN, authenticated tunnel, or reverse proxy for any route that leaves a trusted network.

Remote client checklist

  1. 1
    Start locally first

    Confirm curl http://127.0.0.1:8787/health succeeds on the host.

  2. 2
    Add the network boundary

    Expose only the route your devices need and terminate TLS at a controlled boundary.

  3. 3
    Pass HTTP and WebSocket

    The web/mobile client needs regular API calls plus WSS upgrades at /ws.

  4. 4
    Use the public HTTPS URL

    Enter that same URL in the browser or mobile profile.

  5. 5
    Test authenticated flow

    Sign in, list a project, open a session, and verify live output before relying on remote access.

Credentials and transport

Browser sessions, bearer tokens, and WebSocket authentication are meaningful only when the transport is protected. A proxy must preserve authorization headers and WebSocket query authentication where used. Prefer HTTPS/WSS everywhere outside a private local development path.
