The Web workspace is the primary remote desk for an io-workbench host. It gives one authenticated browser view to projects, configured agent CLIs, files, Git evidence, database work, and a live host terminal.

First browser session

  1. 1
    Open the server URL

    Use the local address from Quick start, or the HTTPS address configured by your remote-access boundary.

  2. 2
    Sign in or finish setup

    First-user setup creates the local account. The standard password form requires a username of at least 3 characters and a password of at least 6 characters.

  3. 3
    Add an existing host project

    In the sidebar, choose + Add project, browse to an existing directory on the host, then add it. The browser picker does not create or clone folders. Prepare the directory through a trusted host workflow first, or use the separate native-desktop/protected-API workspace flow when appropriate.

  4. 4
    Check the host tools

    Open Settings → Agents → CLI Status. Treat its installed/authenticated result as a readiness hint, then prove the selected provider with one small, non-destructive task before opening a paid or long-running session.

Start an agent session

  1. 1
    Choose the project

    Keep the code, Git state, Shell working directory, and session history tied to one project context.

  2. 2
    Select the provider, then configure the prompt

    On an empty Chat, choose Claude, Codex, or Gemini to select the host CLI and focus the composer. Use the Prompt config (flask) button beside the composer to load compatible models and choose model, mode, or effort before sending.

  3. 3
    Give the agent a bounded task

    State the goal, relevant paths, constraints, and validation command. A focused first task makes the code/Git review loop easier to verify.

  4. 4
    Review or stop streamed work

    Follow the response as it arrives. While a turn is running, Send becomes Abort chat; stop it before changing a task that is no longer safe or useful.

  5. 5
    Resume instead of restarting context

    Sessions and assistant output are persisted. Reopen a previous session to continue the project conversation rather than rebuilding context in a new tab.

Reconnect behavior

A dropped browser connection does not move the work to the client. The server keeps the session/process context and can replay persisted output after the browser reconnects.

A practical first task

  1. 1
    Add the host project

    The browser's Sidebar → + Add project picker accepts an existing directory. Prepare one through a trusted host workflow first, then browse to it, add it, and check the displayed path before touching files or commands.

  2. 2
    Verify the agent CLI

    Go to Settings → Agents → CLI Status, then run one small, non-destructive task with the selected Claude, Codex, or Gemini CLI before relying on it for a larger job.

  3. 3
    Create the Chat session

    On an empty Chat, select the provider. Open Prompt config (flask) beside the composer to choose model/mode/effort, then send a bounded plan that names the expected validation command.

  4. 4
    Inspect Files and Git

    Open Files, select a file from the tree, use Edit or Preview, then Save intentional changes. Open Git, select changed rows, review Diff/File Review, stage the intended files, enter a commit message, then use Commit Selected.

  5. 5
    Add data evidence when needed

    Open the Command palette with Command or Ctrl/Cmd+K, select Open Database Explorer, then choose New. Fill the connection form, use Test Form, then Save Connection. Select the saved connection and use Explorer or SQL → Run Query for a narrow check.

  6. 6
    Run Shell validation

    Select Shell to start or reuse a PTY in the chosen project, then run the relevant test, build, migration, or lint command on the host. Restart replaces that PTY; Stop kills it.

  7. 7
    Track and close the work

    For reviewable substeps, open Board, enter a Board Prompt, choose provider/model and Git Policy (the default is Read Only), then use Add To Board. Review the backlog and explicitly start it with Start board tasks; creating a backlog does not execute it.

Web UI boundaries

Files

No device-local checkout

The browser views and edits the server project through authenticated APIs. It is not an editor backed by browser storage.

Agents

No hosted model proxy

The selected CLI runs in your host environment using the credentials and provider setup you control.

Shell

No browser shell

Shell input, resize, output, abort, and process visibility target a server-hosted PTY.

Remote use

Treat it as a control plane

Use HTTPS/WSS and a narrow network boundary when this URL leaves the trusted local machine.
